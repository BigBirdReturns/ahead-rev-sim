§ 01

Why Reversible Execution

Standard execution overwrites state; history is lost, and every erased bit costs energy. Reversible execution runs the same program forward and backward, deriving prior state algebraically instead of recording it.

The power wall is real. Moore's Law ended. Dennard scaling ended. Data centers are commissioning nuclear plants. Compute demand keeps growing while joules per operation stopped falling.

The physics is settled. Landauer's principle: irreversible computation must dissipate kT·ln 2 per erased bit. Reversible computation approaches zero dissipation in the limit. Bennett, Fredkin, and Toffoli proved the theory decades ago.

The gap is tooling. The theory exists. The silicon doesn't. The toolchain doesn't. Nobody has a usable reversible execution environment where architects and compiler writers can test assumptions before RTL investment.

This is working code. A RISC-V style core with reversible execution lanes: algebraic inversion, branch-safe undo chain, energy modeling, assembly-driven execution, and a time-travel debugger. MIT licensed. Fork it.

§ 02

The ISA

Two lanes, one instruction stream. Reversible ops are algebraically inverted — no state snapshots. Branches store minimal history: one taken-bit plus the source PC. Irreversible ops run as usual and are counted against the reversibility ratio.

InstructionSemanticsInverseLane
Reversible — inverted algebraically, zero history
RXOR rd, rs1 rd = rd XOR rs1 self-inverse Reversible
RADD rd, rs1 rd = rd + rs1  (mod 2³²) subtract rs1 Reversible
RSWAP rd, rs1 swap rd ↔ rs1 self-inverse Reversible
Control flow — minimal history: 1 bit + source PC
BEQ rs1, rs2, label branch if equal restore PC from record 1-bit history
Irreversible — standard ops, state overwritten
ADD rd, rs1, rs2 rd = rs1 + rs2 — Irreversible
SUB rd, rs1, rs2 rd = rs1 − rs2 — Irreversible
LOAD rd, rs1, imm rd = mem[rs1 + imm] — Irreversible
STORE rs1, rs2, imm mem[rs1 + imm] = rs2 — Irreversible
HALT stop execution — Terminal

§ 04

Time-Travel Debugging

Run a buggy program. Walk backward to find the bug. No trace buffers, no re-execution from the start — reverse steps derive earlier state directly.

ahead-rev-debug bundled demo 
$ ahead-rev-debug

Program: Compute r1 = 10 + 5 + 3 = 18
Bug: One instruction is RXOR instead of RADD

Forward execution: 7 steps
Expected r1 = 18
Actual   r1 = 15

✗ Mismatch detected!

Beginning reverse execution to locate bug...

  Step back 1: Undid RADD at PC 5
    r1: 15 → 12
  Step back 2: Undid RXOR at PC 4
    r1: 12 → 15
    ⚠ This is a reversible XOR — suspicious!

Bug located at PC 4: RXOR r1 r3

§ 06

The Hot / Cold Dual Pipeline

The endgame is not replacing CMOS — it's a dual pipeline on shared silicon. Legacy code still runs. Reversible code runs too. The simulator models both lanes so the split can be evaluated before anyone commits to RTL.

Hot Pipelinestandard CMOS · today
  • irreversible ALU ops
  • high frequency / high drive
  • current workloads, unchanged
Cold Pipelinereversible · next
  • reversible ALU primitives
  • adiabatic switching window
  • future low-power workloads
Shared: registers · memory · ISA decode · page tables · OS ABI
§ 07

Energy Model

Every executed instruction charges the energy model. The default costs are deliberately simple — a relative accounting, not a SPICE run — so kernels can be compared by how much of their work lands in the cold lane.

Together with the reversibility metrics (reversible count, irreversible count, per-opcode counts, reversibility ratio), this answers the planning question: which instruction patterns deserve reversible hardware first?

Reversible op — cost 0.1

Inverted algebraically; approaches the adiabatic limit. No bits erased, no kT·ln 2 floor.

Irreversible op — cost 1.0

Overwrites state. Pays the Landauer floor per erased bit — the baseline all savings are measured against.

Reversibility ratio

Fraction of a kernel that can, in principle, execute on an adiabatic or reversible unit. Tracked per program, per opcode.

§ 08

Quick Start

Install + Run bash 
$ git clone https://github.com/BigBirdReturns/ahead-rev-sim
$ cd ahead-rev-sim && pip install -e .

# Time-travel debugger (the demo that makes it click)
$ ahead-rev-debug

# History buffer analysis (answers silicon sizing questions)
$ ahead-rev-history

# Reversible memory preview (bridge to v0.8)
$ ahead-rev-memory

# Run your own programs
$ ahead-rev-sim run program.asm

For Silicon Engineers

Buffer sizing from history-depth analysis. Instruction-mix ratios per kernel. Memory-interface and bandwidth trade-offs from the hot/cold controller model. Bits-per-instruction as a proxy for buffer area cost.

For Compiler Engineers

Mark basic blocks reversible and let the toolchain guarantee algebraic invertibility. Reversible ops update in place — liveness analysis matters. A prototype target for region-marking passes and LLVM intrinsics (v0.9).
