# v0.9 Reversibility Frontier Acceptance Train

Version 0.9 changes `ahead-rev-sim` from an instruction demonstration into a workload-to-architecture evidence producer. The release is accepted only when the same deterministic workload can be traced from accepted output through information semantics, reversible lowering, execution equivalence, reverse restoration, architecture pressure, and a physically testable break-even envelope.

## Authority boundaries

`ahead-rev-sim` may establish instruction semantics, information loss, candidate lowerings, exact simulator state, history and ancilla pressure, modeled domain crossings, and normalized break-even conditions. It may not establish recovered electrical energy, measured joule savings, thermal closure, occupied volume, timing closure, fabrication viability, or a universal EVP score.

A mnemonic is never sufficient evidence of reversibility. Admission is determined from the instantiated state transform, including operand aliases. Workload success is never inferred from execution completion alone. An accepted-output contract must name the result, quality rule, accepted work unit, and stable contract identity.

## Gates

### Gate 0: semantic soundness

- Reject collapsing aliases such as `RXOR r1, r1` and `RMODADD r1, r1`.
- Classify every operation as native reversible, conditionally reversible, irreversible, commit, or invalid.
- Record intrinsic erasure, overwritten state, path metadata, hazards, and admissible lowerings.
- Produce bounded exhaustive collision witnesses for supported ALU transforms.

### Gate 1: deterministic frontier artifact

- Bind source bytes, normalized instruction encoding, architecture assumptions, and accepted-output contract.
- Emit a deterministic SHA-256-sealed artifact.
- Preserve strategy vectors for history, ancilla, extra operations, commits, crossings, restoration coverage, energy parity, and runtime parity.
- Refuse a scalar score that conceals policy weights.

### Gate 2: deterministic workload import

- Import all Future AI Microbench Suite workload identities without changing their inputs or acceptance rules.
- Classify all seven workload shapes.
- Preserve source, build, input, expected-output, and result hashes.

### Gate 3: executable lowering

- Lower at least one structured arithmetic, one memory-irregular, and one composite workload.
- Prove forward output equivalence against the original workload.
- Prove exact entry-state restoration for each admitted reversible region.
- Emit first-divergence evidence when either proof fails.

### Gate 4: architecture pressure and break-even closure

- Produce Pareto-visible history, ancilla, recomputation, uncomputation, latency, and crossing strategies.
- State the minimum physical recovery, maximum cold-domain slowdown, maximum transition overhead, and maximum support-memory cost required for parity.
- Keep every energy value marked normalized until a physical measurement receipt replaces it.

### Gate 5: external audit and physical handof

- Package the frontier artifact, workload evidence, simulator inputs, and deterministic replay materials for artifact-only reconstruction.
- Export a candidate physical-measurement contract without asserting that the measured result exists.
- Require an independent acceptor before any end-to-end physical advantage is qualified.

## Current transaction

The first v0.9 transaction closes Gate 0 and the deterministic core of Gate 1. Gates 2 through 5 remain open and must consume these contracts rather than replacing them with dashboard state or prose claims.
