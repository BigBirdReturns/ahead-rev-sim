# v0.9 Reversibility Frontier Acceptance Train

Version 0.9 changes `ahead-rev-sim` from an instruction demonstration into a workload-to-architecture evidence producer. The release is accepted only when the same deterministic workload can be traced from accepted output through information semantics, reversible lowering, execution equivalence, reverse restoration, architecture pressure, and a physically testable break-even envelope.

## Authority boundaries

`ahead-rev-sim` may establish instruction semantics, information loss, candidate lowerings, exact simulator state, history and ancilla pressure, modeled domain crossings, and normalized break-even conditions. It may not establish recovered electrical energy, measured joule savings, thermal closure, occupied volume, timing closure, fabrication viability, or a universal EVP score.

A mnemonic is never sufficient evidence of reversibility. Admission is determined from the instantiated state transform, including operand aliases. Workload success is never inferred from execution completion alone. An accepted-output contract must name the result, quality rule, accepted work unit, and stable contract identity.

## Gates

### Gate 0: semantic soundness

- Reject collapsing aliases such as `RXOR r1, r1` and `RMODADD r1, r1`.
- Classify every operation as native reversible, conditionally reversible, irreversible, commit, or invalid.
- Record intrinsic erasure, overwritten state, path metadata, hazards, and admissible lowerings.
- Produce bounded exhaustive collision witnesses for supported ALU transforms.

### Gate 1: deterministic frontier artifact

- Bind source bytes, normalized instruction encoding, architecture assumptions, and accepted-output contract.
- Emit a deterministic SHA-256-sealed artifact.
- Preserve strategy vectors for history, ancilla, extra operations, commits, crossings, restoration coverage, energy parity, and runtime parity.
- Refuse a scalar score that conceals policy weights.

### Gate 2: deterministic workload import

- Import all Future AI Microbench Suite workload identities without changing their inputs or acceptance rules.
- Classify all seven workload shapes.
- Preserve the source repository, commit, source Git blob identities, harness, common result contract, configuration, reference result rows, and observed result-stream hash.
- Derive the result-stream shape from the pinned source rather than assuming one row per benchmark name.
- Preserve reference documentation even when its row count, bench distribution, or notes diverge from the pinned source.
- Bind each accepted result to schema, suite version, contract identity, benchmark, mode, iteration count, semantic result, result interpretation, producer acceptance, and one explicit clock kind per observed stream.
- Refuse timing comparison until an observed stream independently matches the complete result contract.

### Gate 3: executable lowering

- Lower at least one structured arithmetic, one memory-irregular, and one composite workload.
- Prove forward output equivalence against the original workload.
- Prove exact entry-state restoration for each admitted reversible region.
- Emit first-divergence evidence when either proof fails.
- Prove the combined state map before charging path-history bits to data-dependent control.
- Apply ordinary compiler optimizations symmetrically to conventional and reversible baselines.

### Gate 4: architecture pressure and break-even closure

- Produce Pareto-visible history, ancilla, recomputation, uncomputation, latency, and crossing strategies.
- State the minimum physical recovery, maximum cold-domain slowdown, maximum transition overhead, and maximum support-memory cost required for parity.
- Keep every energy value marked normalized until a physical measurement receipt replaces it.
- Admit designed devices, stochastic thermodynamic substrates, oscillators, reservoirs, embodied structures, and harvested environments through one typed substrate contract.
- Keep operand, dynamics, energy, context, and result channels separate so sensing, computation, and energy harvesting cannot be conflated.

### Gate 5: external audit and physical handoff

- Package the frontier artifact, workload evidence, simulator inputs, and deterministic replay materials for artifact-only reconstruction.
- Export a candidate physical-measurement contract without asserting that the measured result exists.
- Require an independent acceptor before any end-to-end physical advantage is qualified.
- Preserve an ordinary RISC-V MMIO queue binding as the portable floor, with any `Xphys` custom extension treated as an optional acceleration path.
- Require a software fallback for every physical substrate class so implementations compete as substitutable cartridges rather than proprietary execution islands.

## Current transaction

The first v0.9 transaction closes Gate 0 and the deterministic core of Gate 1. Later transactions close bounded parts of Gates 2 through 4 while retaining the unproven boundaries named below.

### Transaction 2 evidence

The history-complete strategy is executable on the repository fixture. It proves sparse accepted-output observations, reverses every executed instruction, removes memory words that were absent at entry, and restores the exact architected entry-state hash. This supplies the first executable point beneath Gate 3.

### Transaction 3 evidence

The physical-compute boundary is a commodity cartridge interface rather than a commitment to one processor, one material, or one thermodynamic mechanism. The interface declares physical quantities, units, calibration, sample timing, reset semantics, determinism, entropy custody, environment boundary, energy-source class, software fallback, and a sealed execution receipt. A deterministic RC-like relaxation cartridge and a trace-replay stochastic thermal sampler exercise the same portable runtime. A harvested-world reservoir descriptor admits a plant, structure, body, weather field, fluid, oscillator network, or other evolving environment as a candidate substrate without granting it a compute capability before a workload proves useful memory, separation, stability, and readout quality.

The portable floor is `physical-compute-mmio/v1`; `Xphys` is an optional non-standard RISC-V acceleration path that cannot change the descriptor or evidence boundary. Reference execution proves contract behavior and replay conditions only. Physical compute, recovered or harvested energy, occupied volume, timing, and thermal closure remain blocked until measured receipts replace the software fallback evidence.

### Transaction 4 evidence

The complete FAMBS v0.3.2 workload identity is captured at commit `a57c72d46c601fa253b8bc1acda5c37b31f8264e`. All seven workloads carry source Git blob identities, exact configuration, architectural class, semantic capability requirements, emitted note identities, and accepted-output gaps.

### Transaction 6 evidence

The first structured workload lowering reproduces the FAMBS v0.4.0 `SVK` result `000000004700158d` with separate IEEE-754 binary32 multiply and add rounding. It applies loop-invariant dot-product motion to both the conventional parity baseline and every reversible strategy so ordinary compiler optimization cannot be misreported as physical recovery.

The fair conventional baseline contains 1,512 normalized semantic operations. The reversible frontier contains eleven nondominated checkpoint schedules. Its minimum-work endpoint uses 32,032 support bits and 4,051 operations. Its minimum-support endpoint uses 2,048 support bits and 8,179 operations. Every point copies the contracted output and restores reference entry state with zero modeled erasure. The normalized zero-support physical-recovery requirement ranges from 62.6758825 percent to 81.5136325 percent across the frontier.

The artifact exports `binary32_sparse_dot` and `binary32_stateful_recurrence` as candidate physical operators behind the commodity substrate contract. RISC-V code generation, target floating-point parity, physical execution, measured timing, energy, volume, and thermal closure remain blocked.

### Transaction 7 evidence

The memory-irregular `PCK` lowering proves that data-dependent control does not automatically require path history. The generated 1,024-state index transition contains two branch-local maps. The odd-payload branch has 512 outputs, the even-payload branch has 512 outputs, their image sets are disjoint, and their union covers all 1,024 successor indices exactly once. The successor index therefore identifies the predecessor index and branch without a stored path bit.

The inverse transition table and modular accumulator subtraction restore every default 128-step chase. The LCG-based pool initialization is also reversed by reconstructing each swap from the final seed and the modular inverse of the multiplier. Payload and next-index arrays are recomputed into clean targets rather than logged.

The retained-final-state frontier contains ten nondominated points. Retaining no chase endpoints uses 42 peak reversible-state bits and 541,185 normalized operations. Retaining all 256 endpoints uses 10,752 bits and 279,041 operations. Every point reproduces the accepted result `0000000006de4698`, restores the outer sink, restores every chase, restores pool construction, and records zero path-history bits and zero modeled erasure. The zero-support recovery threshold ranges from 74.2195368 percent to 50.0001792 percent as retained state increases.

The resulting architecture class is `state_recoverable_piecewise_permutation`. Candidate RISC-V support includes efficient indexed loads, modular add and subtract, a read-only inverse-transition table, and a reversible local-state retention hint. These remain architecture consequences rather than an admitted ISA extension.
