# Pylon-guided architecture projection

The congruent-shape atlas identifies structures recurring across the 73 admitted commodity records. The architecture projection asks a stricter question: where does each pylon already exist in `ahead-rev-sim`, which invariants are qualified, which remain open, and what next transaction should shape the implementation?

Two machine-readable artifacts preserve both history and progress:

```text
src/ahead_rev_sim/data/congruent_shape_surface_projection.json
src/ahead_rev_sim/data/pylon_surface_advances_2026_08.json
```

The base projection records the state when the pylon atlas was introduced:

```text
contract_implemented   9
partial_contract       8
mapped_open            2
```

The advance overlay records later evidence without rewriting that history. The effective state is now:

```text
contract_implemented  12
partial_contract       7
mapped_open            0
```

`contract_implemented` means that the deterministic software contract, refusal behavior, schema, fixture, and tests exist. It does not imply measured physical closure. `partial_contract` means that the pylon has real surfaces but still lacks one or more implementation or evidence stages. `mapped_open` means that the ecosystem shape has been identified without an executable reference subsystem. No current pylon remains mapped-open.

## Implemented contracts

The bounded transition spine is present in accepted-output, execution, restoration, and consist proofs. Provider authority is constrained through the commodity registry and hitch contracts. Negative-space refusal is represented in MMIO, provider, physical-substrate, remote-venue, causal-custody, and EVP blockers. Self-describing cartridges use `physical-compute-mmio/v1`, typed descriptors, explicit capabilities, reset, fallback, and receipts. Reference twins execute through the same physical runtime. The lifecycle state machine distinguishes done, refused, and fault outcomes. The held-out physical assay separates computation from sensing. EVP is a non-scalar Pareto vector. Registry-gap dispatch converts every public record into a bounded transaction and lane.

Three additional pylons now have deterministic reference contracts:

- `scale-seam-communication-tax` attributes movement, synchronization, retry, latency, energy, occupied allocation, utilization, and failure domains to adjacent scale seams;
- `remote-venue-envelope` seals a venue-neutral packet, verifies raw returns and accepted output locally, and compares the same packet across distinct reference venues; and
- `causal-custody-braid` maps multiple clock domains into one interval, proves explicit causal edges under uncertainty, and binds workload, calibration, environment, power, thermal, trace manifests, determinism, and accepted output.

These contracts retain their measured and external blockers. Software-reference closure means that the implementation target is now replaceable and testable. It does not mean the target has supplied evidence.

## Partial contracts

Provenance is SHA-256 sealed but does not yet carry a complete signed source-to-measurement transformation chain. Semantic lowering covers instantiated instructions plus SVK and PCK, while composite lowering and executed Chipyard RTL remain open. Model fidelity distinguishes reference, simulated, and measured tiers, but no measured staircase has replaced the reference cartridges. The complete-system envelope and EVP schema exist, while a closed physical boundary does not. Composition is specified through MMIO, provider hitches, and a Chipyard candidate, while RTL and physical transport remain open. The materialization funnel reaches source-bound generator artifacts but not elaborated RTL or fabricated test structures. Intermittent recovery has strategy and energy contracts but no shared failure-trace execution.

Causal custody moved out of this section at the reference tier. Its remaining work is evidence ascent: OpenTelemetry semantics, Perfetto trace integration, PTP or White Rabbit clock measurements, physical entropy, measured instrument intervals, and independent reconstruction.

## Fan-out surfaces

The second-wave staging registry contains 25 external candidates distributed across scale seams, remote venues, and causal custody. It remains separate from the admitted commodity registry. A candidate can be promoted only after source and license identity, an ahead adapter, a deterministic fixture, a schema-valid receipt and refusal path, and substitute coverage have been qualified.

The immediate adapter sequence is:

```text
Chakra trace profile
→ ASTRA-sim, gem5, FireSim, Accelergy, and 3D-ICE reference comparisons

WES or TES submission profile
→ RO-Crate audit bundle
→ two real venue returns and migration after denial

OpenTelemetry semantic conventions
→ Perfetto causal trace
→ LinuxPTP or White Rabbit measured clock mapping
→ instrument framework adapters
```

## Design rule

A new feature should not be justified only by the local mechanism it enables. It should identify the pylon it strengthens, the authority boundary it preserves, the current surface it extends, the open invariant it closes, and the receipt that proves the change. A new commodity record should project onto the pylon atlas before it can enter an execution lane. A staged candidate should not enter the admitted registry until promotion is explicit. A retired provider or programme should leave the same pylon coverage behind through substitutes.

The control question is: which contract-implemented pylon now ascends from software reference to target-observed or measured evidence, and what receipt proves that movement without weakening an upstream authority layer?
