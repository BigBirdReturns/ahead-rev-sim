# Congruent-shape design pylons

The commodity registry contains projects that appear unrelated when classified by material, institution, or market. Reversible processors, probabilistic samplers, neuromorphic systems, photonic fabrics, chiplet standards, open PDKs, remote testbeds, molecular languages, intermittent runtimes, measurement daemons, and national programmes nevertheless repeat a small number of causal structures. Those repeated structures are the design pylons.

A congruent shape is not a shared word or visual analogy. It is the same movement of agency, state, authority, evidence, and cost across unlike substrates and scales. The pylon catalog records the invariant, the actor that retains authority, the collapse the design must forbid, the minimum surfaces required to preserve the shape, the failure modes that reveal its absence, and a proof transaction that can exercise it.

The resulting atlas maps all 73 commodity records and all 26 registry gaps onto 19 pylons. Four foundation pylons apply to every record. Fifteen domain pylons arise from recurrent structures in the public ecosystems. Every pylon carries curated witnesses from at least two distinct ecosystem categories, and every selected commodity receives at least two domain pylons in addition to the four foundations.

## Foundation pylons

### Bounded transition spine

The recurring transaction is:

```text
frozen base
+ bounded task packet
+ replaceable worker
        ↓
candidate transition
        ↓
hidden deterministic verifier
        ↓
immutable receipt
        ↓
replay from frozen base
        ↓
comparative report
```

MLCFlow, open photonic fabrication runs, remote neuromorphic systems, and RISC-V verification all need this shape. The actor executing the work is allowed to produce a candidate transition. It is not allowed to redefine the base, task, verifier, accepted output, or comparison.

### Authority outside provider

AheadComputing, Vaire, ARIA testbeds, standards bodies, foundries, and open-source tools are execution or evidence suppliers. Workload identity, acceptance, fallback, evidence, publication, and succession remain programme authority. An offer, implementation, measurement, and independent acceptance are distinct states.

### Negative-space refusal ledger

A complete architecture must represent refusal, fault, missing evidence, unmeasured state, not-applicable state, and accepted state separately. Ambiguity becomes a terminal refusal with a blocker ledger and a bounded next transaction. Programme cancellation and failed fabrication are therefore evidence rather than deletion events.

### Provenance and succession chain

The durable chain is:

```text
source
→ model or build
→ execution
→ measurement
→ acceptance
→ supersession
```

Every edge retains identity and replay material. A vendor, maintainer, facility, or grant may disappear without erasing the accepted historical transaction.

## Domain pylons

### Self-describing cartridge

UCIe, CXL, NIR, physical-compute cartridges, neuromorphic targets, photonic links, and reversible devices all require identity, descriptor, capabilities, lifecycle, state, reset, fallback, and receipt surfaces. The implementation may change. The transaction and evidence boundary do not.

### Reference-twin substitution

Normal's `thermox`, CrossSim, ReservoirPy, AIHWKit, compact-model simulators, and software neuromorphic backends repeat the same shape. A physical candidate and public reference twin execute the same accepted workload. First divergence is preserved. Hardware arrival never deletes the fallback.

### Lifecycle refusal state machine

Chipyard peripherals, chiplet links, remote queues, intermittent runtimes, roots of trust, and physical cartridges all need explicit discovery, configuration, loading, execution, readout, capture, reset, refusal, and fault transitions. Transport completion is not task acceptance.

### Causal custody braid

Thermodynamic, probabilistic, event-driven, environmental, biological, and measurement systems require state, entropy or path trace, environment, calibration, and synchronized time to remain coupled. A run identifier cannot substitute for those causal objects.

### Semantic IR lowering sandwich

CIRCT, Calyx, NIR, Verilog-A, molecular languages, RISC-V lowering, and accelerator generators share a layered shape:

```text
accepted domain semantics
→ portable representation
→ target lowering
→ target execution
```

Differential verification spans every edge. Target vocabulary does not become semantic authority.

### Model-fidelity staircase

The recurring evidence order is:

```text
ideal
→ nonideal
→ calibrated
→ target-observed
→ measured
→ independently validated
```

CrossSim, OpenVAF, SPICE, electromagnetic solvers, photonic compact models, PDKs, and molecular simulators expose different sections of the same staircase. Each transition identifies what physical evidence replaced the earlier abstraction.

### Compute-versus-sensing separation

Physical reservoirs, plants, bodies, molecular systems, neuromorphic devices, and analog arrays must separate raw stimulus, sensed input, substrate response, readout, training, and accepted task result. The same held-out readout is applied to raw stimulus and substrate response. Positive task gain, with training and acquisition cost retained, is the admission boundary for useful physical computation.

### Complete-system envelope

A primitive sits inside host, memory, movement, conversion, control, sensing, readout, package, board, cooling, and environmental support. Vaire, Normal, photonic fabrics, neuromorphic systems, and analog arrays all risk promoting a bounded component metric into a system claim. The envelope keeps every required actor inside the same accepted-work interval.

### EVP Pareto frontier

Energy, Volume, throughput, and latency remain a vector. Candidate and baseline must share workload, accepted work unit, boundary, claim scope, and environment. Complete-system advantage requires the candidate to be no worse in every dimension and strictly better in at least one. No provider chooses a scalar weighting that hides a regression.

### Composition fabric

Chiplet, coherent-memory, photonic, board, and host interfaces repeat the pattern of replaceable endpoints joined by a stable transport profile. Opaque handles, endpoint lifecycle, errors, retries, coherency, package topology, security, and transfer cost remain visible.

### Scale-seam communication tax

Tile, die, package, board, rack, and facility boundaries introduce movement, synchronization, refresh, utilization, and failure costs. Hala Point, photonic rack fabrics, UCIe, and SRC heterogeneous-integration programmes are congruent here. A local device result cannot be multiplied across a scale seam without a new receipt.

### Materialization funnel

The physical-design transaction is:

```text
semantics and source
→ generated implementation
→ signoff
→ fabrication
→ package
→ test
→ measured receipt
```

OpenROAD, open PDKs, openEBL, photonic PDKs, mixed-signal generators, and open neuromorphic tape-outs occupy different stages of the same funnel. Failed runs and alternative routes remain part of the estate.

### Remote venue envelope

A remote system is a replaceable venue:

```text
sealed submission
→ queue and facility identity
→ execution
→ raw returned artifacts
→ local replay
→ acceptance or migration
```

EBRAINS, THOR, ARIA, national prototyping facilities, and fabrication programmes repeat this shape. A dashboard summary is not a reconstructable run.

### Intermittent commit and recovery

Checkpointing, task-atomic execution, reversible history, retries, and physical-cartridge execution must be compared under identical work, state, failure, and energy traces. Retained progress, commit boundaries, lost work, storage, sensing, reset, and recovery energy remain separate.

### Registry-gap transaction dispatch

Every public signal is converted through the same intake spine:

```text
public signal
→ pinned identity
→ reusable commodity asset
+ named system gap
→ bounded first transaction
→ completion lane
→ required receipt
→ substitution
```

OCP workstreams, national programmes, open communities, vendor announcements, and terminated initiatives become useful because they expose a system seam and a transaction. They do not become platform authorities.

## How the pylons guide the architecture

The pylons define the order in which surfaces should appear. Accepted semantics and authority precede implementation. A replaceable cartridge and lifecycle precede physical claims. State, entropy, environment, calibration, and time precede replay. A reference twin and fidelity staircase precede model transfer. Complete-system boundaries precede EVP comparison. Provenance and refusal surround every stage.

The current design spine is:

```text
bounded transition
→ external authority
→ refusal ledger
→ provenance and succession
→ semantic lowering
→ self-describing cartridge
→ lifecycle
→ causal custody
→ reference twin
→ fidelity staircase
→ compute separation
→ composition and scale
→ materialization
→ complete-system envelope
→ EVP Pareto comparison
→ remote venue and intermittent recovery
→ registry-driven substitution
```

This sequence is not a waterfall. It is an authority hierarchy. Later stages may add evidence. They cannot silently replace earlier contracts.

## Claim boundary

The atlas establishes congruent causal structures in the registered public ecosystem and converts them into design and proof constraints. It does not establish that a witness actor has implemented `ahead-rev-sim`, accepted a hitch, supplied evidence, or achieved a physical or EVP advantage.

The control question is: which pylon invariant must remain stable when a commodity is replaced, scaled, refused, materialized, measured, or abandoned?
